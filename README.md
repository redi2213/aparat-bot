# aparat-bot

ربات تلگرامی برای دانلود فایل از **پیام‌های عمومی تلگرام** (لینک مستقیم یا فوروارد) و از **لینک‌های مستقیم http/https**، بدون نیاز به سرور همیشه‌روشن.

## معماری

```
Telegram  --webhook-->  Cloudflare Worker  --repository_dispatch-->  GitHub Actions  --release/upload-->  Telegram
                              ↑                                              |
                              └──────────── /internal/history-add ───────────┘
```

- **Worker** فقط پیام تلگرام رو می‌گیره، تشخیص می‌ده چیکار باید بشه، و کار سنگین رو با یک event به GitHub Actions می‌سپاره. سبک و سریع، بدون هزینه‌ی هاست.
- **GitHub Actions** کار سنگین (دانلود، آپلود Release) رو انجام می‌ده و هر ۱۰ ثانیه یک پیام تلگرام با پیشرفت به‌روز می‌کنه.
- فایل نهایی به‌صورت **GitHub Release asset** ذخیره می‌شه و لینک مستقیمش برای کاربر ارسال می‌شه.
- وقتی کار موفق تموم بشه، Actions یک درخواست کوچک به Worker می‌زنه (`/internal/history-add`) تا آیتم توی تاریخچه‌ی همون کاربر در Cloudflare KV ثبت بشه — چون Actions مستقیم به KV دسترسی نداره.

> نوار پیشرفت چطور کار می‌کنه؟ برای **لینک تلگرام**، `tdl dl` در پس‌زمینه اجرا می‌شه و چون حجم کل فایل از قبل معلوم نیست، فقط بایت‌شمار/سرعت نشون داده می‌شه. برای **لینک مستقیم http/https**، معمولاً سرور `Content-Length` می‌ده، پس **درصد واقعی** پیشرفت هم نشون داده می‌شه. در هر دو حالت، هر ۱۰ ثانیه‌ی یک‌بار **همون یک پیام تلگرام** با `editMessageText` به‌روز می‌شه (نه پیام جدید)، تا rate limit تلگرام رعایت بشه. برای **آپلود** (`gh release create`)، چون بایت‌شمار واقعی قابل‌دسترسی نیست، بعد از اتمام دانلود حجم فایل رو داریم و یک تخمین ساده (بر پایه‌ی یه سرعت متوسط فرضی) از زمان باقی‌مانده نشون می‌دیم، و هر ۱۰ ثانیه فقط زمان سپری‌شده رو آپدیت می‌کنیم تا کاربر مطمئن بشه کار متوقف نشده.

## ساختار پوشه‌ها

```
worker/
├── index.js              # نقطه ورود Worker - routing، تایید webhook، endpoint داخلی history-add
├── telegram/
│   ├── client.js          # توابع خام API تلگرام (send/edit/answerCallback)
│   ├── forward.js          # تشخیص فوروارد + نوع فایل پیام
│   ├── directUrl.js         # تشخیص لینک مستقیم http/https + بررسی حجم با HEAD request
│   ├── menus.js             # تعریف کیبوردها و متن منوها
│   └── handlers.js         # منطق اصلی: هندل پیام و callback
├── github/
│   └── dispatch.js         # ارسال repository_dispatch به GitHub (شامل zip/custom_name)
└── state/
    ├── session.js            # session در حال پیکربندی هر کاربر (rename/zip) در Cloudflare KV
    ├── activeJob.js           # job در حال اجرا (run_id، messageId) برای پشتیبانی از دکمه لغو
    ├── users.js               # ادمین (از secret) + کاربران مجاز (در KV، قابل افزودن از داخل ربات)
    └── history.js             # تاریخچه‌ی ۲۰ فایل آخر هر کاربر، جدا و مستقل از بقیه

actions/
├── common/
│   └── notify.py            # پیام‌رسانی مرحله‌ای + ProgressReporter/HeartbeatReporter + ثبت تاریخچه
├── telegram_download/
│   └── download.py           # اجرای tdl/gh با نوار پیشرفت زنده + گزارش مراحل + rename/zip
└── direct_url_download/
    └── download.py            # دانلود استریم لینک مستقیم http/https با درصد پیشرفت واقعی + gh + rename/zip

.github/workflows/
├── telegram-to-release.yml       # trigger: repository_dispatch (telegram_download) یا دستی
├── direct-url-to-release.yml     # trigger: repository_dispatch (direct_url_download) یا دستی
└── deploy-worker.yml              # trigger: push به worker/** یا wrangler.toml — دیپلوی خودکار Cloudflare
```

## قابلیت‌های فعلی

- ✅ دریافت لینک پیام عمومی تلگرام (`t.me/channel/id`) و دانلود با `tdl`
- ✅ دریافت **لینک مستقیم http/https** به یک فایل (از هر سایت دیگه) و دانلود استریم با درصد پیشرفت واقعی
- ✅ تشخیص پیام فوروارد شده (از کانال/گروه/شخص) و نوع فایل داخلش (ویدیو، عکس، موزیک، سند، ...)
- ✅ اگر فوروارد از کانال/گروه با یوزرنیم عمومی باشه، لینک `t.me` به‌صورت خودکار ساخته و مسیر دانلود طی می‌شه
- ✅ دانلود بدون تغییر/Encode مجدد
- ✅ نوار پیشرفت زنده برای دانلود (حجم/سرعت برای تلگرام؛ درصد کامل برای لینک مستقیم) — ادیت یک پیام هر ۱۰ ثانیه
- ✅ پیام heartbeat با تخمین زمان باقی‌مانده در طول آپلود Release
- ✅ **دکمه‌ی لغو دانلود** روی پیام پیشرفت — واقعاً workflow run رو در گیت‌هاب کنسل می‌کنه (برای هر دو مسیر تلگرام و لینک مستقیم)
- ✅ نام فایل تمیز (بدون پیشوند chat-id/message-id که `tdl` پیش‌فرض اضافه می‌کنه)
- ✅ محدودیت حجم برای لینک مستقیم: بدون سقف برای ادمین، حداکثر ۲ گیگابایت برای کاربر عادی (چک‌شده قبل از شروع دانلود، با HEAD request)
- ✅ منوی اصلی (`/start` یا `/menu`) با دسترسی سریع به راهنما/تاریخچه/تنظیمات
- ✅ **دکمه‌ی بازگشت به منو** بعد از هر پیام نهایی (موفق، ناموفق، خطا) — همیشه یه راه برگشت هست، بدون نیاز به `/start` دوباره
- ✅ منوی چندگزینه‌ای قبل از پردازش (هم برای تلگرام هم لینک مستقیم): تغییر نام فایل و ZIP، قابل ترکیب با هم
- ✅ **تاریخچه‌ی فایل‌ها**: ۲۰ مورد آخر هر کاربر، با دکمه‌ی کپی لینک و حذف
- ✅ **چند کاربره**: یک ادمین (شما، از `USER_ID`) و کاربران عادی که فقط تاریخچه‌ی خودشون رو می‌بینن؛ ادمین از داخل منوی تنظیمات کاربر جدید اضافه/حذف می‌کنه (فوری، بدون دیپلوی مجدد)
- ✅ **تفکیک تاریخچه برای ادمین**: قبل از نمایش، ادمین انتخاب می‌کنه بین تاریخچه‌ی خودش، تاریخچه‌ی یک کاربر خاص (جدا)، یا نمای ترکیبی همه — تاریخچه‌ی کاربران هیچ‌وقت خودکار با هم قاطی نمی‌شن
- ✅ **حذف فایل کاربر توسط ادمین**: ادمین از داخل تاریخچه‌ی هر کاربر می‌تونه فایل نامناسب رو حذف کنه، بدون این‌که به تاریخچه‌ی خودش دست بخوره
- ✅ اعتبارسنجی webhook با `X-Telegram-Bot-Api-Secret-Token`

### درباره‌ی منوی گزینه‌ها

بعد از اینکه لینک/فوروارد شناسایی شد، یک منو با گزینه‌های قابل‌ترکیب نشون داده می‌شه:

- **✏️ تغییر نام** — با زدن دکمه، ربات منتظر پیام بعدی شما (نام جدید، بدون پسوند) می‌مونه
- **📦 ZIP** — فایل نهایی رو قبل از آپلود به Release فشرده می‌کنه
- **▶️ شروع پردازش** — کار رو با ترکیب گزینه‌های فعلی به GitHub Actions می‌سپاره؛ بلافاصله بعدش یک پیام پیشرفت با دکمه‌ی **⛔ لغو دانلود** ارسال می‌شه

### درباره‌ی لغو دانلود

دکمه‌ی لغو، workflow run مربوطه رو واقعاً روی گیت‌هاب کنسل می‌کنه (نه فقط مخفی‌کردن پیام). چون شناسه‌ی دقیق اجرا (`run_id`) بلافاصله بعد از dispatch در دسترس نیست، Worker چند ثانیه در پس‌زمینه دنبالش می‌گرده — اما این تاخیر مانع شروع خود دانلود نمی‌شه (دانلود همون لحظه‌ی dispatch شروع می‌شه). اگه کاربر خیلی زود دکمه‌ی لغو رو بزنه، ربات یک چک سریع دیگه انجام می‌ده و لغو رو کامل می‌کنه.

### درباره‌ی تاریخچه و کاربران

- هر کاربر عادی با زدن دکمه‌ی **🕘 تاریخچه فایل‌ها** مستقیم ۲۰ مورد آخر **خودش** رو می‌بینه؛ کنار هر ردیف دو دکمه هست: 🔗 برای دریافت دوباره‌ی لینک، 🗑 برای حذف از تاریخچه.
- **ادمین** اول یک منوی انتخاب می‌بینه: «👤 تاریخچه‌ی خودم»، «👥 کاربر فلان» (برای هر کاربر مجاز، جدا)، یا «📋 همه (ترکیبی)». تاریخچه‌ی کاربران هیچ‌وقت خودکار قاطی نمی‌شن — ادمین باید صریح انتخاب کنه که همه رو با هم ببینه.
- در هر نمایی که ادمین باشه (خودش یا یک کاربر خاص)، دکمه‌ی 🗑 کار می‌کنه — یعنی اگه یک کاربر فایل نامناسبی فرستاد، ادمین می‌تونه از همون‌جا حذفش کنه، بدون این‌که به تاریخچه‌ی خودش دست بخوره.
- افزودن/حذف کاربر فقط از منوی **⚙️ تنظیمات** و فقط برای ادمین در دسترسه: دکمه رو بزنید، آیدی عددی تلگرام طرف رو بفرستید (می‌تونید با @userinfobot پیداش کنید)، همون لحظه فعال می‌شه.

## راه‌اندازی (بدون نیاز به نصب wrangler — مناسب گوشی/ترموکس)

`wrangler` (ابزار خط‌فرمان Cloudflare) روی اندروید/ترموکس اصلاً کار نمی‌کنه، چون یکی از وابستگی‌هاش (`workerd`) برای اندروید build نشده. به‌جاش، یک GitHub Action (`.github/workflows/deploy-worker.yml`) هر بار که فایل‌های `worker/` یا `wrangler.toml` عوض بشن، خودش Worker رو روی سرورهای گیت‌هاب دیپلوی می‌کنه — شما فقط با مرورگر/اپ گیت‌هاب کار می‌کنید، نه خط‌فرمان.

### ۱. ساخت KV namespace (فقط یک‌بار، از داشبورد Cloudflare)

با مرورگر گوشی وارد [dash.cloudflare.com](https://dash.cloudflare.com) بشید:

1. **Workers & Pages → KV** → **Create a namespace**
2. اسمش رو `STATE` بذارید و بسازید
3. یک شناسه (Namespace ID) نشونتون می‌ده — این رو کپی کنید و در فایل `wrangler.toml` به‌جای `REPLACE_WITH_YOUR_KV_NAMESPACE_ID` جایگزین کنید، بعد commit/push کنید

### ۲. ساخت API Token و پیدا کردن Account ID (فقط یک‌بار)

با همون داشبورد:

1. **My Profile → API Tokens → Create Token**
2. از قالب آماده‌ی **Edit Cloudflare Workers** استفاده کنید (دسترسی لازم رو خودش می‌ده) و بسازید
3. توکن ساخته‌شده رو کپی کنید (فقط یک‌بار نشون داده می‌شه)
4. Account ID هم توی همون صفحه‌ی داشبورد (سمت راست، زیر نام اکانت) دیده می‌شه — اون رو هم کپی کنید

### ۳. تنظیم Secrets در ریپوی GitHub (با مرورگر یا اپ گیت‌هاب)

در ریپو: **Settings → Secrets and variables → Actions → New repository secret**، این‌ها رو یکی‌یکی اضافه کنید:

| نام Secret | مقدار |
|---|---|
| `CLOUDFLARE_API_TOKEN` | توکنی که در مرحله‌ی ۲ ساختید |
| `CLOUDFLARE_ACCOUNT_ID` | Account ID مرحله‌ی ۲ |
| `TELEGRAM_TOKEN` | توکن ربات از BotFather |
| `USER_ID` | آیدی عددی تلگرام خودتون — شما ادمین می‌شید (مثلاً از @userinfobot بگیرید) |
| `GH_TOKEN` | یک Personal Access Token گیت‌هاب با دسترسی `repo` (از Settings → Developer settings → Personal access tokens بسازید) |
| `WEBHOOK_SECRET` | یک رشته‌ی رندوم دلخواه (مثلاً چند کلمه‌ی تصادفی) |
| `INTERNAL_SECRET` | یک رشته‌ی رندوم دیگه (فرق داره با WEBHOOK_SECRET) — برای اینکه Actions بتونه امن به Worker برای ثبت تاریخچه زنگ بزنه |
| `WORKER_URL` | آدرس Worker بعد از اولین دیپلوی (مثلاً `https://aparat-bot.YOUR-SUBDOMAIN.workers.dev`) — این رو بعد از مرحله‌ی ۴ اضافه/آپدیت کنید |
| `TDL_SESSION` | base64 سشن `tdl` برای دانلود از تلگرام (این یکی رو باید از قبل روی یک سیستم دیگه با `tdl` تولید کنید) |

### ۴. دیپلوی

فقط کافیه فایل‌ها رو push کنید (همون کاری که با ترموکس انجام می‌دید):

```bash
git add .
git commit -m "update"
git push
```

چون `worker/**` یا `wrangler.toml` عوض شده، تب **Actions** ریپو رو باز کنید — یک workflow به اسم **Deploy Worker to Cloudflare** خودکار اجرا می‌شه و Worker رو دیپلوی می‌کنه. می‌تونید از همون تب پیشرفتش رو ببینید (سبز = موفق).

> اگه فقط فایل‌های `actions/` یا `.github/workflows/telegram-to-release.yml` / `direct-url-to-release.yml` رو عوض کردید (نه `worker/`)، نیازی به دیپلوی مجدد Cloudflare نیست — این‌ها مستقیم توسط GitHub Actions در زمان اجرا خونده می‌شن.

اگه هیچ فایلی عوض نشده ولی می‌خواید یه‌بار دیگه دستی دیپلوی رو اجرا کنید: تب **Actions → Deploy Worker to Cloudflare → Run workflow**.

### ۵. ثبت Webhook تلگرام (فقط یک‌بار، بعد از اولین دیپلوی موفق)

آدرس Worker رو از داشبورد Cloudflare (Workers & Pages → aparat-bot) کپی کنید — همون آدرس رو هم به‌عنوان secret به اسم `WORKER_URL` در گیت‌هاب اضافه کنید (مرحله‌ی ۳)، هم این لینک رو یک‌بار در مرورگر گوشی باز کنید (به‌جای `<TOKEN>` و بقیه مقادیر، مال خودتون رو بذارید):

```
https://api.telegram.org/bot<TOKEN>/setWebhook?url=https://<your-worker>.workers.dev&secret_token=<WEBHOOK_SECRET>
```

جواب `{"ok":true,...}` یعنی موفق بوده.

## نقشه‌ی راه (قابلیت‌های بعدی)

فهرست کامل قابلیت‌های درخواستی در بک‌لاگ پروژه ثبت شده و به‌مرور اضافه می‌شن: صف دانلود، دکمه‌ی لغو/تلاش مجدد، نمایش اطلاعات فایل قبل از دانلود، پاک‌سازی خودکار فایل‌های قدیمی و غیره.
